# מערכת ניהול לקוחות לכלכלת המשפחה

Next.js + Supabase (Postgres, Auth, Storage) + Prisma. פרויקט נפרד לגמרי מ-עזרי, בעבור ישראל שרמן (מרצה לאוריינות פיננסית + יועץ משכנתאות).

## מה כבר בנוי ונבדק מקצה לקצה (בלייב, לא רק build)

- **Auth לקוח**: כניסה עם קוד חד־פעמי למייל (Supabase Auth, OTP). `src/app/login`
- **Auth יועץ**: אותו מנגנון OTP בדיוק, אבל `Advisor.authUserId` במקום `FamilyMember.authUserId` — מפנה ל-`/admin` במקום `/dashboard`. `src/lib/advisor.ts`
- **DB**: סכמת Prisma מלאה (`prisma/schema.prisma`), מחוברת לפרויקט Supabase אמיתי (`qgexfrmmjrbsnswtmyaf`).
- **מיילים**: SMTP מותאם מול Resend. **שני** תבניות מייל תוקנו להציג קוד גלוי ({{ .Token }}) — גם "אישור הרשמה" וגם "Magic Link or OTP" הנפרדת (משתמשים חוזרים עוברים דרכה, לא דרך הראשונה — קל לפספס).
- **דשבורד תקציב**: קטגוריות, הוצאות, מנגנון קיזוז (reallocation) לפי ה-PRD, הוצאות קבועות/חוזרות עם checkbox. `src/lib/budget.ts`, `src/app/dashboard`
- **שאלון קליטת לקוח**: משוחזר מהטופס האמיתי של ישראל ב-Google Forms (forms.gle/F2XrbsX4uLnZYDGE7), data-driven (`formSchema.ts`), עיצוב מותאם למותג (נווי/זהב/קרם), ללא login, גישה לפי טוקן. `src/app/onboarding/[token]`
- **סיכומי פגישות ללקוח**: מוצגים באזור האישי של הלקוח יחד עם "על מה נתמקד בשלב הבא". `src/lib/meetings.ts`
- **אזור יועץ (`/admin`)**: רשימת משפחות → עמוד משפחה עם (א) העלאת מסמכים/הקלטות ל-bucket פרטי ב-Storage עם signed URL, (ב) הוספת סיכום פגישה. שני הטפסים כפופים ל-`assertFamilyOwnedByAdvisor` (יועץ יכול לגעת רק במשפחות שלו). `src/app/admin`
  - הוספת סיכום פגישה — **נבדק בלייב**, עובד.
  - העלאת קובץ — קוד תקין (אותו דפוס storage+signed-url שכבר עובד), **לא נבדק בלייב** כי דפדפן ה-agent לא תמך בהעלאת קובץ אמיתי. צריך בדיקה ידנית חד־פעמית.

## הערה חשובה על Resend

בלי אימות דומיין משלך, Resend שולח רק לכתובת המייל שאיתה נרשמת ב-Resend. **לפני שלקוחות אמיתיים יכולים להתחבר, צריך לחבר דומיין** (Resend → Domains → Add Domain, ואז כמה רשומות DNS). זה גם ישפר את אמינות המסירה (פחות סיכוי לתיקיית ספאם). ראינו בפועל שמיילים חוזרים ("Magic Link or OTP") לפעמים לא הגיעו ל-Gmail תוך דקות למרות שResend הראה "Delivered" — כנראה reputation issue של הדומיין המשותף של Resend תחת traffic חוזר ומהיר. לא בעיה בקוד.

## מה סוכם ונדחה במפורש (לא לגעת בלי שישראל מעלה מחדש)

- **וואטסאפ**: הושהה לפי בקשה מפורשת ("בא נחכה עם החיבור של הווצאפ").
- **תמלול הקלטה → טיוטת מייל סיכום → אירוע יומן**: ישראל בחר במפורש שעזרי יעשה את זה **ידנית** דרך הג'ימייל/יומן האמיתיים שלו, ולא כפיצ'ר במערכת — ואז חזר בו וביקש שיהיה אפשר **להעלות את ההקלטה עצמה** לתיקיית הלקוח בתוך המערכת (זה מה שנבנה ב-`/admin`). השלב הבא בשרשרת (תמלול אוטומטי + טיוטת מייל + יומן) עדיין לא נבנה ולא סוכם איך בדיוק — צריך להחליט עם ישראל.

## המשך מכאן (session חדש)

1. תבקש מישראל לבדוק ידנית העלאת קובץ ב-`/admin/families/[id]` (אין דרך לבדוק את זה מהדפדפן הפנימי).
2. אם עובד — אין עוד dev פתוח בשלב הזה, אפשר לשאול את ישראל מה הפיצ'ר הבא (WhatsApp? תמלול אוטומטי? back-office מורחב?).
3. אם לא עובד — לקרוא `src/app/admin/families/[id]/actions.ts` (`uploadDocument`) ו-`src/lib/supabase/admin.ts`, ולדבג משם.
